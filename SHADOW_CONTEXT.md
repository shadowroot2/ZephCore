## Предпочтения пользователя

- Анонс разделять на «из основной прошивки» и «доработки ShadoW»; не выдавать

## CLI

- Любое добавление, удаление, переименование или перемещение команды делать
  согласованно в обработчиках, USB CLI, BLE CLI, remote LoRa CLI и
  `docs/COMMANDS.MD`. Учитывать различия ролей и capability.
- Companion vContact предназначен только для уведомлений. На любую входящую
  команду отвечать: `Please use the command line in Settings; this chat is for
  notifications only.`
- BLE `MAX_FRAME_SIZE` — 176 байт. Для help учитывать тип пакета, трёхбайтовый
  CLI-префикс и NUL; доступно не более 172 байт текста.
- Tagged remote reply — не более 158 байт с NUL. После правки help измерять
  каждый вариант конфигурации, а не длину исходной строки.
- Секретные и опасные команды не публиковать в remote help. Точная текущая
  доступность и дерево — только в `docs/COMMANDS.MD`.
- Remote-команды `sos` и `tracking` запускают полностью беззвучный сценарий,
  включая промежуточные и финальные отправки. Локальные UI/USB/BLE сохраняют
  штатные звуки.

## Экраны и управление

- После обновления автора сравнивать обе реализации: `ui-button` и
  `ui-joystick`. Capability проверять через DT/Kconfig, не по имени платы.
- Заставка: ZephCore, `MeshCore on Zephyr`, версия, дата и нижняя подпись
  `Tuned by ShadoW`.
- Не терять страницы и порядок из `docs/SHADOW_FEATURES.md`, особенно GPS,
  Tracking, SOS, WiFi, Buzzer, LEDs, Sensors, Offgrid, DFU и Shutdown.
- E-Paper не имеет фоновой перерисовки: setter любого видимого асинхронного
  состояния обязан запросить render после фактического применения состояния.
- GPS переключается асинхронно. Callback main thread передаёт UI `enabled` и
  фактический `OFF/ACQUIRING/STANDBY`, затем вызывает `ui_request_render()`.
  Пользователь аппаратно подтвердил 2026-10-27: после OFF → ON GPS-страница
  обновляется корректно.
- На плате с физическим переключателем GPS UI отражает переключатель и не
  пишет `GPS not detected`, когда питание GPS физически выключено.
- WiFi endpoint показывать одной строкой `IPv4:port`; отдельной строки порта
  нет. Изменение WiFi on/off сохраняется и выполняет cold reboot.
- SOS на странице SOS: при активном SOS одно нажатие отменяет его, проигрывает
  звук отмены Fall при наличии buzzer и отправляет `❌ SOS Canceled`.
- Ручное выключение показывает `Power OFF`; low-battery экран M1 не затирается
  в течение grace period.

## Уведомления и кнопки

- vContact получает уведомления о локальных изменениях SOS, GPS, Tracking,
  LEDs, buzzer, Fall и выключении кнопкой. Точный текст сверять с кодом и
  `docs/SHADOW_FEATURES.md`.
- Карты нажатий T-1000E и M3 должны оставаться одинаковыми там, где совпадают
  capability. При активном SOS одно нажатие отменяет SOS.
- Fall доступен только по capability акселерометра; не использовать board-name
  gates.

## Аппаратные инварианты

- M6: GPS Air530Z/L76K — `GPS_EN=P0.06`, `GPS_STANDBY=P0.30` HIGH;
  `GPS_RESET` не трогать. Пользователь подтвердил GPS fix. Заряд определяется
  `EXT_CHRG_DETECT=P0.15`, active-low уже учитывается GPIO API; ручная инверсия
  запрещена. Solar telemetry `6 W` относится только к M6.
- T-1000E: USB определяется только `EXT_PWR_DETECT=P0.05`; CHRG не использовать
  как признак полного заряда. Fall на QMA6100P подтверждён пользователем;
  текущие пороги и штатные clock/filter не менять без нового измерения.
- Heltec V3: USB CLI идёт через CP2102/UART0; нужен serial companion transport,
  console/shell на UART0 выключены. Release-образ только merged BIN с offset
  `0x0`; signed app расположен в slot0 `0x10000`. VBAT multiplier — 5420.
- XIAO nRF52840: провайдеры VBUS и процента батареи задаются до `ui_init()`;
  зарядная индикация как у M3/T-1000E — 1/2/3 импульса, полный заряд постоянно.
- T-Echo не имеет аппаратного buzzer. Красный LED не должен постоянно гореть
  только из-за показания батареи 0%.

## Сборка и артефакты

- Перед каждой сборкой сначала показать точные board/role/options и цель,
  затем получить подтверждение пользователя.
- Использовать `./.venv/bin/west` и:
  `ZEPHYR_SDK_INSTALL_DIR=/Users/shadow/Work/CodeX/ZephCore/zephyr-sdk-1.0.1`,
  `CCACHE_DIR=/private/tmp/zephcore-ccache`.
- При смене платы или роли — `--pristine`; ESP32-S3/C-series — `--sysbuild`.
- Все локальные build trees хранить в `builds/` и передавать west путь
  `-d builds/<board>-<role>`; не создавать `build*` в корне.
- Артефакты складывать в `firmware/`. Имя:
  `<board>-<role>-<commit>.<ext>`, например
  `t1000_e-companion-a4733b1e6.uf2`. Сохранять штатные подчёркивания платы.
- ESP: `<board>-<role>-<commit>-merged.bin` и при необходимости `-update.bin`.
  Для прошивки пользователю отдавать merged BIN с offset `0x0`.
- HEX не создавать без явной необходимости.
- После сборки сообщать Flash/RAM, для ESP также IRAM/DRAM. Предупреждения не
  скрывать.
